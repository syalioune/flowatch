## Scope

**IN** — 8 look × theme combinations × 4 text-on-background pairs = **32 contrast computations**.

**OUT**:
- **Densities** (`html[data-density="compact|regular|comfy"]`) — declare only `--gap` / `--row-h` / `--pad` / `--fs` sizing variables. Grep-verified at [src/styles/tokens.css:186-201](../src/styles/tokens.css#L186-L201): no colour tokens are overridden per density. If a future density variant adds colour the test scope expands to 24 combinations (8 × 3); see the migration note in the test file header.
- **`ACCENT_PALETTES`** (runtime accent overrides at [src/app.tsx:26-32](../src/app.tsx#L26-L32)) — operator-pickable, NOT part of the shipped baseline. A future story may audit each entry.
- **Modeler internals** (`.djs-container` / `.bpmn-host` / `.dmn-host`) — bpmn-js / dmn-js ship their own theming; out-of-tree.
- **Hover / focus / active state contrast** — covered conceptually by Pattern P-008 but no current invariant. Future story may extend.

## Summary

**32 of 32 pairs pass.** 7 pairs were below the AA threshold at audit time; all 7 were fixed in the same `feat:` commit via trivial OKLCH lightness bumps (≤ 12 lightness points per token; no chroma or hue change; comments inline in [tokens.css](../src/styles/tokens.css) name the lift). 0 issues filed; 0 exceptions documented.

> **Forward-pointer (Story 32.2, 2026-06-14).** This token-math audit checks
> four text/background pairs. The axe-core DOM audit
> [a11y-audit-1.0.0.md](a11y-audit-1.0.0.md) later found `color-contrast`
> failures on token pairs this math never examined — the status-chip
> (`.ep-method`) and badge (`.badge[data-tone]`) coloured labels over their
> faint same-hue tint backgrounds. Story 32.2 added dedicated on-tint
> foreground tokens `--ok-fg` / `--warn-fg` / `--bad-fg` / `--info-fg` (light
> variants OKLCH-lightness-lowered, hue/chroma preserved — same precedent as
> the bumps below) and extended the Pattern P-008 guard
> ([wcag-contrast.test.ts](../src/__tests__/wcag-contrast.test.ts)) with those
> on-tint pairs. The two audits agree: the 32 pairs here still pass; the
> chip/badge tint pairs are covered in the 1.0.0 audit.

All 7 fixes are single-line OKLCH lightness bumps; no chroma or hue mutations. Visual character of each look is preserved — only the muted-text and (in one case) accent shades shift slightly darker (light themes) or slightly lighter (dark themes). The `.kpi-lbl` / `.nav-label` / `.tbl th` / `.empty` / `.drawer-sect` / `.brand-tag` consumers of `--fg-mute` gain legibility at small font sizes.

## Re-run cadence

This audit document is dated (`a11y-audit-YYYY-MM.md`) and is a snapshot of the state-of-the-art at audit time. The CI regression guard at [src/__tests__/wcag-contrast.test.ts](../src/__tests__/wcag-contrast.test.ts) enforces the invariant on every commit — a token edit that drops a pair below AA breaks CI.

A new dated audit document (e.g. `a11y-audit-2026-08.md`) should be re-authored when:
- A new look variant is added (e.g., a future "monochrome" or "high-contrast" look).
- A new theme variant is added (e.g., a "sepia" theme between light and dark).
- A new audited pair is added (e.g., focus-ring contrast — out of 17.3 scope).
- 12 months have passed (annual cadence) regardless of changes.

The next audit reuses this document's structure verbatim.
